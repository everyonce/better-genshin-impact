BetterGI English interface build

Run BetterGI.exe from this folder. Keep the entire folder together.
This portable package includes .NET and starts with English interface and game
language settings. It does not replace an existing BetterGI installation.

The fork translates built-in menus, settings, dropdown displays, dialogs,
notifications, log templates, map editor and script repository browser controls.
Chinese storage keys, script identifiers, paths and recognition data are retained
where required for compatibility. Your existing script/configuration files can
therefore continue to use their original identifiers.

Downloaded routes/scripts can have author-written Chinese titles, descriptions,
settings and log output. User text and recognized game text are not automatically
machine-translated. External websites and upstream documentation retain their
own languages. Built-in app translation does not translate third-party content.

Updates: the Check for Updates command opens this fork's releases:
https://github.com/everyonce/better-genshin-impact/releases
The upstream automatic installer is not used, because it replaces this English
build. Download and unpack a new English portable build separately.
If the release page is empty, no downloadable update has been published there.
The English-Web-Source folder contains the embedded frontends' upstream pins,
patches, display dictionaries and licenses for rebuilding them.

Build from source (PowerShell, .NET 8 SDK, Node.js/npm, Git):
  ./Build/EnglishWeb/build.ps1
  ./Build/Scripts/publish-english.ps1

Validation:
  ./Build/Scripts/check-english.ps1
  dotnet test Test/BetterGenshinImpact.EnglishTest -c Release -p:Platform=x64

English dropdown tests exercise WPF controls on an STA thread and check that
language changes preserve saved option values. Static coverage checks scan
translation calls and visible XAML literals. These checks do not certify game
automation behavior; translation verification does not require launching a game.

Translation maintenance: en.json contains dynamic display keys as well as static
XAML/C# keys. The sync tool preserves unmatched English keys intentionally.

Auto Combo: HTTP endpoints on localhost or private LAN addresses are supported.
LAN hostnames must resolve exclusively to private/loopback addresses. Public
endpoints still require HTTPS. Local HTTP servers may leave the API key blank.
Enter the API base URL ending in /v1, not /v1/chat/completions.

English auto-entry: the game-loading trigger recognizes the English "Click to
Begin" prompt with OCR in the lower center of the game window and clicks its
detected location. Existing Chinese template recognition is retained.
Windowed Genshin is supported inside Desktop Clone. Keep a 16:9 game resolution;
map tracking requires at least 1920x1080. Restart BetterGI after changing the
game resolution. Desktop Clone now defaults to a 2560x1440 remote desktop;
Control Center > Desktop Resolution can select 2560x1440 or 1920x1080.

Optional automatic desktop sign-in: Control Center > More > Remember Windows
sign-in opens a local password dialog. Credentials are stored only in Windows
Credential Manager for the current Windows user, not in BetterGI config files.
Use the same account/password that works in the Windows RDP prompt. Saving
does not verify the password; the next connection performs authentication.
Forget saved Windows sign-in removes this app's saved credential. Failed saved
sign-ins fall back to normal Windows prompting rather than repeatedly retrying
the same password; saving a corrected sign-in enables a fresh attempt.

English r6 includes experimental commission pilots for A Returning Customer,
Adventurer Exam: Battle Tactics, and Question and Answer. The package's menus,
settings and runner messages are English. In JS Script, add English Commission
Pilots to a Scheduler group and open its custom script settings. Use English
game text at 1920x1080. Select the matching active commission in J before running.
See User/JsScript/AutoCommissionEnglishPilots/README.txt for manual steps and
limitations. These pilots are source-tested; live gameplay is not yet verified.

The runForQuest path API leaves dialogue under script control and propagates
route failures. Legacy pathing APIs retain their behavior. "Do not choose an
option" now also blocks AutoSkip's fallback selection after an OCR miss.
Pilot regression tests (Node.js):
  node --test Test/EnglishCommissionPilots/*.test.cjs

Tutorial development: r7 adds a default-off AllowNonMainUiStart Scheduler-group
JSON setting. Only a group whose loaded projects all opt in bypasses the normal
HUD startup wait. OpeningQuestPilot provides local screenshot/OCR observations
and supervised, bounded commands with foreground checks. It is an experimental
development tool, not a verified opening-quest route. Input defaults off. See
User/JsScript/OpeningQuestPilot/README.txt for the protocol and limitations.

Live r7 validation on 2026-10-10: the supervised pilot completed Wanderer's
Trail with English game text at 1920x1080. Completion was verified from the
game's completion banner and the next quest, Bird's Eye View, in the journal.
The pilot was stopped there. This is a verified supervised run, not an
unattended route or a live test of the same workflow inside Desktop Clone/RDP.
